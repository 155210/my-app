# gproxy 岛 交接文档

> 新会话接手前先读完这份，再读同目录 `README.md`。最后更新：2026-11-06。

## 1. 这是什么、给谁用

一个仿灵动岛的安卓悬浮窗 App：屏幕顶部一颗黑色胶囊，显示用户本机 gproxy 的今日用量、请求进行中、完成/失败、预算。

用户环境（决定很多设计）：

| 项 | 情况 |
| --- | --- |
| 手机 | 小米，型号 2410DPN6CC，Android 16，澎湃 OS 3（有系统「超级岛」，但第三方普通悬浮窗进不去） |
| Termux | GitHub 版（`TERMUX_APK_RELEASE=GITHUB`，debug 签名）；已装 Termux:API（GitHub 版 v0.53.0） |
| gproxy | [LeenHawk/gproxy](https://github.com/LeenHawk/gproxy) v4.1.14，Termux 里跑，`http://127.0.0.1:8787`，管理员账号 `admin`（密码用户自己在 App 里填，**不要写进仓库**） |
| 酒馆 | SillyTavern 在 Termux 里跑；用户用「柏宝阁」App 打开酒馆网页（见第 6 节）；另外还跑着 clewdr |
| 启动方式 | 用户自己的 `install.sh` 菜单脚本（不在本仓库）：9 = 启动 gproxy，11 = Termux 通知版用量（见第 7 节） |

## 3. 用户最新反馈（待办，按优先级）

### 3.1 「生成中」和「完成绿灯」都没反应 ← 先修这个

用户装了 build 7，发了请求，岛上看不到黄灯也看不到绿灯。**还没定位**，以下是排查线索：

1. **上游日志多半没开。** gproxy 设置里 `enable_upstream_log` 默认 `false`（`crates/gproxy-store/src/entity/config/setting.rs`）。没开时 `GET /admin/api/logs/upstream` 永远是空，「生成中」不可能出现。
   - 下游日志不能用：`DownstreamCapture` 是请求结束才一次性写入（`crates/gproxy-app/src/capture.rs` 注释 "Nothing is written until it ends"）。
   - 上游日志的 `in_progress` 行由 core 的 observer 先建再流式更新（`crates/gproxy-core/src/store_observer.rs`）。**还没在真机验证过开了以后请求进行中是否真的能读到 in_progress**。
   - 建议：App 里读 `GET /admin/api/settings` 的 `logging.enableUpstreamLog`，没开就在设置页和展开的岛里提示，并给一个按钮「一键打开上游日志」→ `PATCH /admin/api/settings`，body `{"logging":{"enableUpstreamLog":true}}`（字段名按 `SettingsPatch`/`LoggingSettingsPatch` 是 camelCase，**发之前对一下源码 `crates/gproxy-sdk/src/dto/settings.rs`**；patch 结构有 `deny_unknown_fields`）。
2. **完成绿灯不依赖上游日志**，靠 `usage/records` 最新一条的 `requestId` 变化判断（`IslandService.fetch()`），按理应该能亮。可能原因：
   - 空闲刷新间隔：`Cfg.interval()` 读 `interval`，初版默认存的是 30 秒，用户点过保存就一直是 30。请求完成后最多 30 秒才发现，绿灯只亮 6 秒，用户可能以为没反应。建议换新 key（如 `interval2`）默认 5 秒，GET 不进审计（见第 5 节），本机请求很便宜。
   - 绿灯只亮 6 秒（`POP_MS`），可以加长，或者收起态保持 `✓` 到下一次请求开始。
   - 酒馆可能不是走 gproxy 而是直连 clewdr：那 gproxy 根本没有记录。让用户确认酒馆 API 地址是 `127.0.0.1:8787`。
   - `recent()` 用的 `page=1` 是对的（`bounds()` 1-based），排序是 `started_at_ms DESC`（`crates/gproxy-sdk/src/query/usage.rs`）。注意按「开始时间」排，长请求完成时可能排不到第一条 → 判断「有新完成」最好改成「出现了上次列表里没有的 id」，而不是只比第一条。
3. **真机没有任何诊断信息**，这是最大问题。建议加「调试」区（设置页或展开岛最下面一行）：上次刷新时间、轮询次数、最新记录 id/时间、in_progress 条数、上游日志开没开、最近错误。让用户截图就能定位。

### 3.2 显示 gproxy 里的「上游额度」，要有查询按钮

用户原话：「gp 里面的上游额度也显示，但是要有个按钮，点查询才查询，不然不查，只显示历史的查询记录」。

gproxy 接口（`crates/gproxy-host-axum/src/admin/config.rs`、DTO 在 `crates/gproxy-sdk/src/dto/quota.rs`）：

| 用途 | 接口 | 说明 |
| --- | --- | --- |
| 列凭据 | `GET /admin/api/credentials?page=1&pageSize=100` | `Page{items,total,…}`，item：`id`、`providerId`、`label`、`status`、`enabled` |
| 列 provider（取名字） | `GET /admin/api/providers?page=1&pageSize=100` | `id`、`name`、`displayName`、`channel` |
| **历史（不打上游）** | `GET /admin/api/credentials/{id}/quota` | `CredentialQuotaDto{cycles, blocks}`；`cycles[]` 先 open 后 closed：`windowId`、`endsAtMs`、`closedAtMs`、`costUsd`、`sample{usedPercent, used, limit, costUsd, atMs}`（= 最近一次读数，`atMs` 就是「上次查询时间」）、`estimatedAllowanceUsd`；`blocks[]`：`untilMs`、`operation` |
| **查询（打上游）** | `POST /admin/api/credentials/{id}/quota-probe` | 返回 `QuotaSnapshotDto{observedAtMs, entries[]}`；entry：`id`、`label`、`kind`（`window`/`rate_limit`/`budget`/`balance`/`breakdown`）、`allowance{used,limit,remaining,usedPercent,unlimited,unit,periodEndMs,resetBehavior}`、`balance{remaining,unit}`。查询后 gproxy 会把读数存成 observation，再 GET quota 就能看到新 sample |
| 原始读数历史 | `GET /admin/api/credentials/{id}/quota-observations?sinceMs&page&pageSize` | 需要「历史查询记录」列表时用 |

UI 要求：默认只调 GET（历史），**只有用户点「查询」才调 POST quota-probe**（会请求上游，可能有频率限制）。放哪里还没定：可以放设置页一个「上游额度」区，每个凭据一行（名字、窗口、已用 %、重置时间、上次查询时间）+「查询」按钮；也可以在展开的岛里放一行摘要。做之前可以问用户。

### 3.3 柏宝阁联动

用户希望「柏宝阁输出完成时岛亮绿灯」。已分析用户给的 `BaiBaoGe-0.4.apk`：

- 包名 `com.baibaoge.mobile`，Capacitor 壳（插件只有 `@capacitor/app`、`@capacitor/status-bar`），本质是**打开酒馆网页的浏览器**：酒馆列表、自动进入、隐藏状态栏、顶部留空、悬浮球后台保活、自动更新。
- **它自己不发 AI 请求、没有对外广播/接口**。生成是酒馆服务端（Termux 里的 SillyTavern）发给 gproxy 的。
- 所以联动的正确做法就是 gproxy 侧检测（3.1 修好即可），与客户端无关。可选增强：岛上点绿灯/长按时 `getLaunchIntentForPackage("com.baibaoge.mobile")` 跳回柏宝阁（manifest 需要 `<queries><package android:name="com.baibaoge.mobile"/></queries>`）。

## 4. 代码结构

见 `README.md`「结构」。要点：

- `IslandService.java`：前台服务（`dataSync`，targetSdk 34 不受 6 小时限制）+ `TYPE_APPLICATION_OVERLAY` 悬浮窗 + `HandlerThread` 轮询。线程约定：`io*` 字段只在轮询线程用，其他 UI 字段只在主线程用，结果通过 `ui.post` 交回。
- 岛的 `y` 最小值 = 状态栏高度 + 2dp（`minY()`）：**状态栏是系统下拉手势区，悬浮窗放进去收不到触摸**（用户踩过）。
- `GproxyClient.java`：登录 + 各接口；`Cfg.java`：SharedPreferences（文件名 `cfg`）和格式化。
- 纯 framework API，没有依赖；UI 全部代码构建，没有 layout XML。

## 5. gproxy API 速查和坑

- **认证**：`POST /portal/api/login {"name","password"}` → `{token, sessionId, expiresAtMs}`。之后请求带 `cookie: gproxy_session=<token>`。**不要用 `Authorization: Bearer`**：管理接口的 bearer 走的是 API Key / OAuth 校验，会 401（源码注释说可以 bearer，实际不行，踩过）。
- `GET /admin/api/usage?fromMs=` → `{summary{requests,inputTokens,outputTokens,cachedInputTokens,cost(字符串)}, groups, trend}`。
- `GET /admin/api/usage/records?page=1&pageSize=N` → `items[]{requestId, model, state(settled/failed/completed…), tokens{inputTokens,outputTokens}, cost, startedAtMs, endedAtMs, durationMs, ttftMs}`。
- `GET /admin/api/logs/upstream?limit=&fromMs=` → `items[]{requestId, state(in_progress/completed/failed/cancelled), model, startedAtMs, firstResponseAtMs, endedAtMs, error, responseStatus}`。
- **GET 不进审计日志**（审计中间件跳过安全方法），高频轮询不会堆审计记录。登录是 POST，只在 token 失效时调。
- 控制台「1d」可能是最近 24 小时；岛统计的是今天 0 点起。

## 6. 构建与发布流程

- 本地没有 Android SDK，沙盒也连不上 Google Maven；只能推到 GitHub 让 Actions 编译（`.github/workflows/gproxyisland.yml`）。
- 流程：从 `origin/main` 拉 `claude/…` 分支 → push → 用 REST 开 PR（`gh pr create` 走 GraphQL 会 403，要用 `gh api repos/155210/my-app/pulls -f …`）→ 等 PR 上的构建通过 → `gh api -X PUT repos/155210/my-app/pulls/<n>/merge` → main 上的构建发 Release `gproxyisland-<run_number>`。
- 签名固定 `gproxyisland.keystore`（密码在 `build.gradle`），覆盖安装不丢设置。
- 推送前可以用 `javac` 粗查语法：`javac -d /tmp/x com/example/gproxyisland/*.java 2>&1 | grep error: | grep -vE "does not exist|cannot find symbol|cannot access"`。
- 下载链接给用户时附代理写法：`https://ghfast.top/<原链接>`。

## 7. Termux 通知版（仓库外，供参考）

用户的 `install.sh` 里加过一个 Termux 通知版（菜单 11 开关，密码存在 `gproxy_dir/.notify_pass`）：每 60 秒用 `termux-notification` 发一条今日汇总 + 最近 3 次各一条。用了悬浮岛后可以关掉免得重复。逻辑和本 App 相同（同样用 cookie 认证）。
