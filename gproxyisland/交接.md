# gproxy 岛 交接文档

> 新会话接手前先读完这份，再读同目录 `README.md`。最后更新：2026-11-06（build 11）。

## 1. 这是什么、给谁用

一个仿灵动岛的安卓悬浮窗 App：屏幕顶部一颗黑色胶囊，显示用户本机 gproxy 的今日用量、请求进行中、完成/失败、预算。

用户环境（决定很多设计）：

| 项 | 情况 |
| --- | --- |
| 手机 | 小米，型号 2410DPN6CC，Android 16，澎湃 OS 3（有系统「超级岛」，但第三方普通悬浮窗进不去） |
| Termux | GitHub 版（`TERMUX_APK_RELEASE=GITHUB`，debug 签名）；已装 Termux:API（GitHub 版 v0.53.0） |
| gproxy | [LeenHawk/gproxy](https://github.com/LeenHawk/gproxy) v4.1.14，Termux 里跑，`http://127.0.0.1:8787`，管理员账号 `admin`（密码用户自己在 App 里填，**不要写进仓库**） |
| 酒馆 | SillyTavern 在 Termux 里跑；用户用「柏宝阁」App 打开酒馆网页（见第 6 节）；另外还跑着 clewdr |
| 启动方式 | 用户自己的 `install.sh` 菜单脚本（不在本仓库）：9 = 启动 gproxy，11 = Termux 通知版用量（见第 7 节） |

## 3. 用户反馈处理情况

### 3.1 「生成中」和「完成绿灯」没反应 → build 11 已修（待真机确认）

**根因（读 gproxy 4.1.14 源码确认）**：`crates/gproxy-core/src/store_observer.rs` 里上游日志的行只在 `persist_capture` 时写库，而它只在「有正文分段要落盘」或「结束」时调用。只开「上游日志」不开「正文」= `CapturePolicy::Metadata`，`bytes()` 直接 return，没有分段 → 请求结束才一次性写入，**进行中永远读不到 in_progress**。旧版设置页提示写的「不用开日志正文」是错的。开了正文（`Full`）后请求体分段 1 秒空闲就落盘，in_progress 行约 1 秒内出现；但之后头信息不再回写，`firstResponseAtMs` 进行中一直是 null，所以不再区分「等待中/生成中」。

改动：
- 读 `GET /admin/api/settings` 的 `logging.enableUpstreamLog` + `enableUpstreamLogBody`；没开在设置页和展开岛里提示，「一键打开」= `PATCH /admin/api/settings {"logging":{"enableUpstreamLog":true,"enableUpstreamLogBody":true}}`。
- **坑**：cookie 认证的非 GET 请求要过同源检查（`gproxy-app/src/auth/csrf.rs`），必须带 `Origin` 且和 `Host` 一致，否则 403 cross-origin。`GproxyClient.request()` 已对非 GET 自动加。
- 新完成判断改为「出现了上次列表里没有的 id」（列表按开始时间排）。
- 刷新间隔换新 key `interval2`，默认 5 秒、范围 3~120（旧 key `interval` 默认 30、最少 10）。
- 绿灯 15 秒；收起态优先级改为 生成中 ＞ 完成提示 ＞ 花费。
- 展开岛最下面「调试」区（设置可关）：刷新次数/多久前、间隔、上次成功、最新记录 id/时间/状态、进行中条数、上游日志/正文开关、读上游日志错误、最近错误。
- 还没排除：酒馆是否真的走 `127.0.0.1:8787`（没走的话调试区「最新记录」不会变）。

### 3.2 上游额度 → build 11 已做

- 设置页「上游额度」区：打开页面自动读历史（`GET /admin/api/credentials`、`/providers`、`/credentials/{id}/quota`，都不打上游），每个凭据一张卡片：窗口名、已用 %、used/limit、剩余、重置倒计时、上次查询时间、限流（blocks）。
- 每张卡片「查询」按钮 → `POST /admin/api/credentials/{id}/quota-probe`（30 秒超时），结果存本机 `cfg` 的 `probe:<credId>`（原始 JSON），之后显示「本机上次查询」和「gproxy 历史 sample」里更新的那个（`Cfg.bestQuota`）。
- 展开岛里每 60 秒（展开时）读一次历史，最多 4 个启用凭据各一行摘要，名字用 `Cred.shortName`（provider + 账户名前 3 位，用户要求）；不会调 probe。
- 「按此速度何时用完」：`Cfg.exhaustAt()`，线性外推 `start + (读数时间-start) × 100 / 已用%`，早于重置才显示（设置页卡片橙字、岛上摘要 ⚠）。start 用 cycle 的 `startsAtMs` / probe 的 `periodStartMs`，不靠谱时用 `重置时间 - 窗口长度`。用户数据验算：7天 51%、周一 14:00 重置 → 周一约 09:40，和 Claude 官方「周一上午耗尽」一致。
- 岛上展开最下面有「⟳ 查询额度」，逐个启用凭据调 quota-probe 并存本机。
- `saveProbe` 在 build 17 之前漏调了（DeepSeek 余额刷新就丢），已修。
- 窗口名映射在 `GproxyClient.windowName()`，只认了 five_hour/seven_day 之类，认不出原样显示。

### 3.2b NovelAI 额度（build 21）

- `NaiClient.java`：照搬柏宝绘（`155210/ST-BaiBai-Image` 的 `src/naiQuota/quota.ts`）口径。`GET https://image.novelai.net/user/subscription`（旧 `api.novelai.net` 后备），`Authorization: Bearer <NAI API Key>`。解析 tier、expiresAt（秒）、`trainingStepsLeft`（fixed + purchased = Anlas）、`usage.percent` / `isNegative` / `timeUntilNextPercent`（V5 免费额度电量）。1% ≈ 17.3 张。

### 3.2c 代理（NekoBox）检测（build 23）

- 用户的代理 App 是 NekoBox for Android（包名 `moe.nb4a`，sing-box 内核，自带 yacd）。
- `ProxyCheck.java`：「开着」= 系统有 VPN 网络 / 有 up 的 tun 网卡 / Clash API 能连上，任一成立（本 App 可能被 NekoBox 分应用代理排除而看不到 VPN 网络，所以多看两样）。节点 = Clash API `GET /proxies` 里名叫 proxy 的 Selector 的 `now`（逐层跟到底），没有就取任意 Selector/URLTest，再没有就取唯一的非内置出站。Clash API 要在 NekoBox 设置里打开「启用 Clash API」（127.0.0.1:9090）。
- 设置页开关 `proxyCheck`（默认关）、`clashApi`、`clashSecret`。每 10 秒查一次；从开着变成没开（含启动时就没开）Toast + 震动一次；没开时收起态红点 + 「⚠ 代理没开 ·」，展开显示节点。
- 真机验证（build 23）：Clash API 能连上，但 NekoBox 生成的 sing-box 配置里主出站 tag 就叫 `proxy`（其余 `g-<id>`、direct/bypass/block），**没有节点名**，所以读不到。
- build 25 改为：`NodeListener`（NotificationListenerService）只读 `moe.nb4a` 常驻通知的标题 = 节点名（SagerNet 的服务通知标题是配置名）；用户要在系统里给「通知使用权」（设置页有按钮）。没给时退回显示 Clash API 里 `proxy` 的协议类型。「开着」= 通知在 或 VPN / tun / Clash API。
- build 30：设置页「检查更新」（`Updater.java`，查 Releases 最大的 `gproxyisland-N`，ghfast 下载后调起安装）；读不到节点名时分别提示「没连上 / 没看到 NekoBox 通知」，启动岛时 `requestRebind`。
- build 31+：打开设置页删掉已装过的更新包；节点改名 `nodeAlias`（每行「原名=新名」，先精确后包含）；**没改名的节点只显示前 3 个字**（用户怕截图泄露），设置页原名默认打码；出口位置 = 走代理请求 `https://www.cloudflare.com/cdn-cgi/trace` 的 `loc`+`colo`（不显示 IP），节点变了立刻重查，否则 5 分钟一次。
- build 36+：指定节点 `allowedNodes`（每行一个，匹配原名 / 改后名 / 出口位置的子串，留空不检查）。开着但不是指定节点 = `wrongNode`：红点、收起态「⚠ 代理错误 ·」、Toast + 震动（和没开同一套，按 `ok()` 由好变坏触发一次）。
- build 39：收起态代理没开 / 代理错误优先级最高。build 40+：设置页「悬浮岛大小」滑条 `scale`（60~140%，缩放字号、内边距、圆角、圆点）；位置 `x/y` 锁定后也沿用（拖好取消勾选 = 锁在那），「位置复原」清掉才回顶部居中。

### 3.2d 最终审核修的 bug（build 53 之后）

- 刷新循环：`poll` 重排前先 `removeCallbacks`。之前刷新进行中点开岛 / 亮屏会多出一条并行循环，请求翻倍到下次熄屏。
- 登录被拒（密码错 / 没填）后 60 秒内不再发登录请求（`GproxyClient.loginDeniedAt`），免得每次刷新往 gproxy 审计日志写一条。
- 指定节点：出口查询失败时先快速重试 2 次（隔 5 秒，`ProxyCheck.exitPending`），期间不判「代理错误」，避免切节点瞬间误报。
- 通知监听断开后不再沿用旧的「NekoBox 通知还在」。
- 服务销毁后（`dead`）丢掉还在路上的后台结果，不再留下每秒空转的计时。
- 请求出错后，恢复的第一次刷新就重读今日汇总；NovelAI 返回不是 JSON 时不覆盖上次的数据；展开时有请求在跑也闪黄灯。
- 仓库公开而签名密钥和密码在仓库里，所以更新不能只靠签名：build 56 起先直连 GitHub 下载，20 秒没数据再退回 ghfast 镜像，安装前把文件 SHA-256 和 GitHub 接口的 `assets[].digest` 比对，不一致就删掉不装（`Updater.Job`）。用户选了这个方案，没有换密钥（换了要卸载重装）。

### 3.2e 界面重做（build 57 之后）

- 颜色和自绘小部件集中在 `Ui.java`（`Glyph` 状态图标、`Bar` 进度条、`Chevron`、`Flow`）。改配色只改这里。
- 岛：`render()` 拆成 `renderPill`（收起态三段：图标 / 主信息 / 次信息，优先级 代理异常 > 连不上 > 生成中 > 刚完成或失败 > 空闲）和 `renderPanel`（展开面板）。调试信息要展开后长按才显示（`showDebug`）。
- `Glyph` 的跳动动画只在挂到窗口上且系统没关动画时才跑，摘下来就停。**不要改成一 `set` 就启动**：无限循环的动画在模拟测试里会让主线程队列永远跑不完，真机上也会在岛被移除后白跑。
- 设置页：单 Activity 分页，`open(p)` 重建内容；后台结果用 `post(gen, …)` 交回，页面换了就丢弃。输入框即时保存；`needRestart` 标记的改动在离开分页（或 `onPause`）时重启岛一次。
- 模拟测试（Robolectric + 假 gproxy，会渲染截图）放在项目文件 `测试/`：`IslandSimTest`、`SettingsSimTest`、`UpdaterSimTest`。测试里要 `ValueAnimator.setDurationScale(0f)`。

### 3.3 柏宝阁联动（用户决定：不做点绿灯跳回柏宝阁，避免别人误点打开泄露）

用户希望「柏宝阁输出完成时岛亮绿灯」。已分析用户给的 `BaiBaoGe-0.4.apk`：

- 包名 `com.baibaoge.mobile`，Capacitor 壳（插件只有 `@capacitor/app`、`@capacitor/status-bar`），本质是**打开酒馆网页的浏览器**：酒馆列表、自动进入、隐藏状态栏、顶部留空、悬浮球后台保活、自动更新。
- **它自己不发 AI 请求、没有对外广播/接口**。生成是酒馆服务端（Termux 里的 SillyTavern）发给 gproxy 的。
- 所以联动的正确做法就是 gproxy 侧检测（3.1 修好即可），与客户端无关。**不要做**跳回柏宝阁（用户明确拒绝，怕别人误点打开泄露）。

## 4. 代码结构

见 `README.md`「结构」。要点：

- `IslandService.java`：前台服务（`dataSync`，targetSdk 34 不受 6 小时限制）+ `TYPE_APPLICATION_OVERLAY` 悬浮窗 + `HandlerThread` 轮询。线程约定：`io*` 字段只在轮询线程用，其他 UI 字段只在主线程用，结果通过 `ui.post` 交回。
- 岛的 `y` 最小值 = 状态栏高度 + 2dp（`minY()`）：**状态栏是系统下拉手势区，悬浮窗放进去收不到触摸**（用户踩过）。
- `GproxyClient.java`：登录 + 各接口；`Cfg.java`：SharedPreferences（文件名 `cfg`）和格式化。
- 纯 framework API，没有依赖；UI 全部代码构建，没有 layout XML。

## 5. gproxy API 速查和坑

- **认证**：`POST /portal/api/login {"name","password"}` → `{token, sessionId, expiresAtMs}`。之后请求带 `cookie: gproxy_session=<token>`。**不要用 `Authorization: Bearer`**：管理接口的 bearer 走的是 API Key / OAuth 校验，会 401（源码注释说可以 bearer，实际不行，踩过）。
- `GET /admin/api/usage?fromMs=` → `{summary{requests,inputTokens,outputTokens,cachedInputTokens,cost(字符串)}, groups, trend}`。
- `GET /admin/api/usage/records?page=1&pageSize=N` → `items[]{requestId, model, state(settled/failed/completed…), tokens{inputTokens,outputTokens}, cost, startedAtMs, endedAtMs, durationMs, ttftMs}`。
- `GET /admin/api/logs/upstream?limit=&fromMs=` → `items[]{requestId, state(in_progress/completed/failed/cancelled), model, startedAtMs, firstResponseAtMs, endedAtMs, error, responseStatus}`。
- **GET 不进审计日志**（审计中间件跳过安全方法），高频轮询不会堆审计记录。登录是 POST，只在 token 失效时调。
- 控制台「1d」可能是最近 24 小时；岛统计的是今天 0 点起。

## 6. 构建与发布流程

- 主流程：推 GitHub main → Actions（`.github/workflows/gproxyisland.yml`）编译发 Release。版本号 = run_number + 10（被封期间本地打到了 45，加 10 保证新版号更大）。
- 备份：同一份代码推到 GitLab main，APK 传 GitLab 通用包仓库 + 建 Release；项目文件 `代码备份/` 放最新代码 zip 和最新 APK。
- 也能在云端沙盒里直接编译：Android SDK 在 `/opt/android-sdk`，Gradle 8.9；`LANG=C.UTF-8` 并给 JVM 加 `-Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8`（不然中文目录名报错），`BUILD_NUMBER=<build>` 决定 versionCode；Maven Central 偶尔 429，跳过 lintVital 任务、`--max-workers=1` 重试即可。
- 签名固定 `gproxyisland.keystore`（密码在 `build.gradle`），覆盖安装不丢设置。
- 推送前可以用 `javac` 粗查语法：`javac -d /tmp/x com/example/gproxyisland/*.java 2>&1 | grep error: | grep -vE "does not exist|cannot find symbol|cannot access"`。
- 检查更新：`Updater.java` 用项目 ID 调 `GET /api/v4/projects/88673288/releases`，私有项目要请求头 `PRIVATE-TOKEN`（用户在设置页填的只读令牌，只存手机）。令牌绝不写进代码或提交。

## 7. Termux 通知版（仓库外，供参考）

用户的 `install.sh` 里加过一个 Termux 通知版（菜单 11 开关，密码存在 `gproxy_dir/.notify_pass`）：每 60 秒用 `termux-notification` 发一条今日汇总 + 最近 3 次各一条。用了悬浮岛后可以关掉免得重复。逻辑和本 App 相同（同样用 cookie 认证）。
